## 3. 방향: 범위는 그대로, 내장 기능은 불러 쓰고 함께 보여 준다

사용자 결정(2026-11-21): 범위를 좁히지 않는다. 프로필 만들기·전환·폴더 추천·설치 시 프로필 고르기·설정 관리 모두 계속 핵심 기능이고,
**모든 기능은 GUI로 보인다**는 원칙(M0~M7 결정)을 유지한다.

피드백의 "겹친다"는 이렇게 다룬다: 내장 기능이 있는 일은 **그 기능을 불러 쓰고**(직접 다시 만들지 않음), Profile Kit 화면에서 **한곳에 모아 보여** 준다.
사용자가 VS Code 여러 메뉴(Profiles 편집기, 확장 보기, 설정 편집기, Settings Sync)를 오가지 않아도 되는 것이 차별점이다.

| 일                                | 내장 기능                                 | Profile Kit                                                                                                |
| --------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 프로필 만들기·전환                | 있음 (UI)                                 | 프리셋대로 한 번에 만들고, 상태 표시줄·트리·폴더 추천에서 전환. 실제 동작은 VS Code를 호출 (지금 방식)     |
| 확장 하나를 모든 프로필에         | 있음 ("Apply Extension to all Profiles")  | `core`로 선언. 내장 표시가 붙은 확장은 트리에 같이 보여 줌 (C-2)                                           |
| 설정 하나를 모든 프로필에         | 있음 (`applyToAllProfiles`)               | 이미 연동 (8-1절, PR #11). 관리 화면에서 목록을 보여 줌                                                    |
| 프로필 파일 공유                  | 있음 (`.code-profile`)                    | 프리셋 ↔ `.code-profile` 변환 (C-1)                                                                        |
| 기기 간 동기화                    | 있음 (Settings Sync)                      | 동기화 자체는 Sync에 맡기고, Sync와 어긋나지 않게 함 (P3, P4) + 미리보기에 "다른 PC로 동기화됨" 표시 (C-3) |
| 구성 전체를 한 파일로 선언 + 이력 | 없음                                      | 핵심                                                                                                       |
| 선언과 실제의 차이 점검, CI 점검  | 없음                                      | 핵심 (`verify`)                                                                                            |
| 설치할 때 넣을 프로필 고르기·추천 | 없음                                      | 핵심                                                                                                       |
| 공통 변경을 모든 프로필에 반영    | 없음 (복사한 프로필은 원본과 연결이 끊김) | 핵심                                                                                                       |
| 폴더 → 프로필 추천                | 없음 (연결만 기억)                        | 핵심                                                                                                       |

한 줄 설명: **"공통 + 용도별 프로필을 한 파일로 선언하고, VS Code 안의 한 화면에서 만들고·맞추고·바꿔 쓰는 도구"**.

## 5. 단계 계획 (M8~)

각 단계는 브랜치 + PR로 진행한다(main 직접 push 불가, ruleset). 게이트(★)는 사용자 확인.

### 단계 A. 품질 기준선과 안정화 — 먼저

0. **SonarQube Cloud 연결 (CI 분석)** — `a-file-icon-vscode`와 같은 방식으로 한다.
   - 조직 `woogajjangka`(이미 있음)에 프로젝트 `WoogaJJangka_vscode-profile-kit`를 만든다 ★(사용자가 SonarQube Cloud에서 직접). 저장소가 private이면 무료 플랜의 private 한도 안인지 만들 때 확인한다.
   - Automatic Analysis는 끄고 CI 분석만 쓴다(둘 다 켜면 CI 스캔이 실패한다).
   - `.github/workflows/sonar.yml`: `SONAR_TOKEN`이 있을 때만 돈다. vitest 커버리지(`@vitest/coverage-v8`, `coverage/lcov.info`)를 함께 올리고, 품질 게이트를 기다려 실패하면 검사 실패. Actions `uses:`는 커밋 SHA + 버전 주석, `permissions: contents: read`(+ `pull-requests: read`).
